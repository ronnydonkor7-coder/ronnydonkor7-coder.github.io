I ran a Linux command in the wrong terminal

I tried to open the dashboard file with nano while I was still in Windows PowerShell. PowerShell returned “nano is not recognized.” I needed to connect to the Pi first, then edit the file there.

nano ~/sentinel-x-dashboard/app.py

That was a useful reminder to check the prompt before running a command. My Windows terminal and the shell on the Pi are different environments.

See the PowerShell error

Getting the app and browser connected

The Flask app runs on 127.0.0.1:5000 on the Pi. Opening localhost on my laptop does not reach that app by itself. I use an SSH tunnel from the laptop to forward the port.

I also checked whether anything was listening on port 5000 before starting the app:

sudo ss -lntp | grep ':5000'

ss lists sockets. The options show listening TCP ports and their processes; grep narrows the output to port 5000. I then started the app with the Python interpreter in its virtual environment.

~/sentinel-x-dashboard/venv/bin/python ~/sentinel-x-dashboard/app.py
See Flask running on the Pi

Checking that an alert really came through

I sent four pings to my router and checked Suricata’s alert log. The rule name was SENTINEL-X ICMP Test Alert. I then checked the same alert in the dashboard.

ping -c 4 192.168.1.1
sudo tail -n 10 /var/log/suricata/fast.log

-c 4 stops after four ping requests. tail -n 10 shows the last ten log lines. This was test traffic on my own network, not an attack.

The dashboard code I’m working on

The app reads /var/log/suricata/eve.json, separates alerts from flow events, and counts them. The table shows the time, source, destination and rule name. I added severity totals and started moving the browser updates to /api/events.
