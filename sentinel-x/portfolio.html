SENTINEL-X 👽

Following network activity from a Suricata alert to an investigation I can explain.

I built a Python/Flask dashboard around the EVE JSON logs from Suricata on my Raspberry Pi 5. This is how I added access control, searched the events, investigated a detection and exported the records.

01

Adding password protection

Before returning alert data, the dashboard now requires a sign-in. I added session-based authentication and checked the behavior in Flask’s request log.

Before authentication

The alert API returned 401 Unauthorized. Opening the dashboard redirected to /login.

After signing in

The login submission redirected to the dashboard. Requests to /api/events then returned 200 OK.

This check demonstrates access control in my local lab; the portfolio page is documentation, not the live dashboard.

02

Reading the network activity

After signing in, I can review events, alerts, network flows and severity counts. The later dashboard also breaks out network protocols and top source addresses.

The current capture shows a recent window of 500 events, 352 network flows and one low-severity alert. These are the records loaded by the dashboard, not lifetime network totals.

03

Finding the alert I want to review

I added a search box for IP addresses or detection names, alongside the severity selector. That gives me a way to narrow the alert list before opening a result.

The browser code normalizes the search text to lowercase and checks it against each alert row. I also call the filter when the table refreshes so new rows follow the selected search.

The later captures include both the search box and “All Severities” selector. I use them to focus the review, while the source logs remain available for context.

05

Keeping the records for further review

The dashboard stores alerts in SQLite and provides an “Export Alert History (CSV)” control. I downloaded the CSV and opened sentinel_x_alerts.csv in LibreOffice Calc to check that the export contained alert records.

The exported data included the retransmission detection. This gives me a record I can examine outside the browser and use alongside my investigation notes.

06

Checking detection from packet to dashboard

I used four pings to my router as controlled traffic, then checked that the custom SENTINEL-X ICMP Test Alert rule appeared in Suricata’s log and in the dashboard.

ping -c 4 192.168.1.1
sudo tail -n 10 /var/log/suricata/fast.log

ping -c 4 sends four requests. sudo runs the log read with elevated permissions, and tail -n 10 shows the last ten lines. I compared the rule name in the terminal with the browser result.

07

What broke while I was building it

Running a Linux command in PowerShell

I tried nano ~/sentinel-x-dashboard/app.py before connecting to the Pi. PowerShell returned “nano is not recognized.” I needed to SSH into the Pi and run the editor there.

Reaching Flask from the laptop

Flask listens on 127.0.0.1:5000 on the Pi. I use an SSH tunnel to reach it from the laptop, rather than expecting the laptop’s localhost to point to the Pi.

Fixing an indentation error

One of my later runs stopped with an “unexpected indent” error near the event-counting code. I checked the indentation and used Python’s compile check while editing the dashboard and analysis files.

The later request log shows the app serving the login flow and alert API again.
